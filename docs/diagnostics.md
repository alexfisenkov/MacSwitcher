# Проверка интеграции

Обычный запуск не открывает тестовые окна и не включает диагностику.
Для установленной по README сборки:
`open -a "$HOME/Applications/MacSwitcher.app" --args --diagnostic-events --diagnostic-panel`.
Сначала выберите выход в меню уже работающего MacSwitcher, иначе новые аргументы
ему не передадутся. Для локальной сборки укажите `.сборки/MacSwitcher.app`.

`--diagnostic-events` пишет только закрытый набор названий этапов в OSLog,
subsystem `com.alexfisenkov.macswitcher`, category `Diagnostics`.
Текст, клавиши, clipboard и пользовательские пути в этот журнал не передаются.
CLI `RuSwitcher --ax-capabilities com.apple.TextEdit` выводит ошибки, типы
и доступность AX-атрибутов без содержимого. Он не запускает приложение.

## Инвентаризация AX-метаданных

Режим доступен в исходниках кандидата alpha.22 и последующих сборках.
В установленной alpha.21 этого аргумента ещё нет.

`--ax-capabilities-metadata` — безопасный режим инвентаризации: он ограничен
метаданными Accessibility и не читает текстовые значения, не вызывает setter,
не меняет TCC-права и не активирует приложение. Каждый AX RPC ограничен 0,25 с;
это предел отдельного вызова, а не всей команды. Результат показывает, какие
роли и атрибуты доступны в текущем контексте. Это не проверка редактирования и
не доказательство runtime-совместимости приложения.

В текущем инвентаре перечислены 181 metadata ID, но это не означает 181
успешно проверенное приложение. В фактическом безопасном прогоне были доступны
62 запущенных bundle ID. Наблюдались, например, `AXTextArea` в TextEdit,
Telegram и Notes и `AXTextField` в Photos. В Chrome текущий `AXGroup` без
сфокусированного текстового элемента означает лишь отсутствие такого элемента
в данном контексте, а не неподдерживаемое приложение. Для остальных приложений
фокус и редактируемость не подтверждены.

Старый `--ax-capabilities` может читать значения атрибутов в памяти, даже если
не сериализует их в вывод; используйте его только с синтетической проверкой.
Для живой инвентаризации предпочтителен `--ax-capabilities-metadata`.

Последние этапы можно прочитать в Terminal:

```sh
log show --last 10m --style compact --info --predicate 'subsystem == "com.alexfisenkov.macswitcher" AND category == "Diagnostics"'
```

Для панели нужен отдельный документ TextEdit с синтетическим содержимым:

1. Выделение: вставить только `ghbdtn`, выделить его целиком, нажать
   `Test selected ghbdtn` в панели. Ожидается `привет` в TextEdit.
2. Ранняя коррекция: включить MacSwitcher и автокоррекцию в меню. Подготовить
   только `ghbd`, снять выделение, поставить каретку в конец. Нажать
   `Test early correction of ghbd`. Ожидается `прив` без пробела.

Панель активирует только TextEdit и принимает только указанные точные fixture.
Она не записывает AXValue: подготовленный латинский префикс передаётся обычному
координатору как уже доставленный payload. PASS требует и callback применения,
и точного read-back результата. При завершении панель показывает итог;
содержимое TextEdit нужно проверить независимо.

Это проверка внутренних путей координатора и конвертера. Она не отправляет
физические Shift и не доказывает получение настоящих HID-событий. Порядок
до отрисовки первого символа покрывается отдельными регрессиями, физический
набор и другие редакторы проверяются отдельно. Ошибка или смена фокуса
прерывает fixture. После проверки перезапустите приложение без `--diagnostic-panel`.

## Экспериментальный клавиатурный транспорт

Начиная с alpha.4 обычный режим блокирует автоматическое программное выделение в Codex.
Для одного синтетического прогона нужны дополнительные аргументы
`--diagnostic-panel --diagnostic-native-canary`. Они включают активный tap,
который возвращает обычные Shift/буквенные события без изменения. Это ограниченный
input gate, не гарантия атомарности внешнего редактора.

Сначала в отдельном TextEdit подготовьте только `ghbd`, каретку в конец и нажмите
`Test native correction of ghbd`. Этот тест вызывает только транспорт:
вставить `прив` после исходника, подтвердить весь дубликат и каретку, затем
клавишами удалить исходные четыре буквы, подтвердить конечный результат.
Clipboard и AXSelectedTextRange setter в этом пути не используются.
Неподтверждённая вставка запрещает удаление; любая неопределённость запрещает
повтор/второй способ записи. Операция синхронная, её бюджет — 100 мс плюс окончание
текущего ограниченного AX-вызова. Перед каждым новым key-down проверяется
дедлайн; key-up уже отправленной клавиши отправляется и при прерывании. События направляются только
захваченному PID и помечаются.

В Codex сами флаги ничего не разрешают. Заранее подготовьте отдельный пустой
черновик и US-раскладку; убедитесь, что MacSwitcher и автоматическое исправление
включены (`autoSwitchEnabled` и `autoConvert`). Native fixture TextEdit не проверяет
эти две настройки. Только после подготовки нажмите `Arm one Codex test (30 s)`;
после этого в течение 30 секунд разрешён только один `ghbd → прив`: US-раскладка, точное целиком
синтетическое поле, каретка 4, без выделения. Другие слова, текст вокруг и
повторные попытки заблокированы. Это эксперимент, а не включение общего режима.
После него перезапустите MacSwitcher без обоих диагностических флагов.
Не считать один успешный прогон подтверждением безопасности поздней доставки.
Если осталось `ghbd`, возник дубль или частичный результат: прекратите ввод,
не повторяйте тест и не меняйте поле до фиксации видимого итога. Верните обычный
запуск без диагностических флагов. Синтетический черновик оставьте отдельно для
разбора; очищать его для завершения теста не требуется. Рабочий текст к нему
не добавляйте. Остановка MacSwitcher, стабильный вид поля и ожидание сами по себе
не доказывают отмену уже отправленных событий.
При неизвестном исходе возможен частичный текст, который не совпадает ни с
исходником, ни с кандидатом результата. Его автоматическое восстановление не
обещается. Неизменный исходник тоже не доказывает отмену уже отправленной native
вставки: такое чтение не очищает pending-состояние. Поколение tap меняется при
остановке/перенастройке/отключении; восстановленный после timeout tap не продолжает
прежнюю транзакцию. Успешная проверка только этого поля не разрешает общий режим.

В alpha.5 неудачный захват фокуса (`focusUnavailable`) допускает только повторное чтение
в оставшемся прежнем бюджете 100 мс, с паузой до 1 мс и пределом 100 запросов.
Каждое чтение сохраняет проверку исходного элемента, PID, revision, secure input
и поколения tap. Это включает ошибку AX, отсутствующее значение или неверный
тип ответа при захвате; диагностическая категория не меняет политику retry.
Установленная смена поля/PID/revision, secure input и потеря gate прекращают
попытку сразу. Во время повторного чтения после `focusUnavailable` новые
клавиатурные события не отправляются, вставка/удаление не повторяются.
Статические `focusReadCannotComplete`, `focusReadNoValue` и другие причины
уточняют отказ AX без содержимого поля. Их дедупликация сбрасывается в начале
каждой native-попытки до предварительного чтения, остальные события не очищаются.
`nativeAutoFocusRecovered` означает
восстановление чтения, а не завершение всей замены. Успех всей операции
по-прежнему требует `nativeAutoVerified` и `autoEditPosted`.

## Жизненный цикл event tap без UI

На Mac с уже выданными Accessibility/Input Monitoring можно запустить
`MacSwitcher.app/Contents/MacOS/RuSwitcher --self-test-event-tap-host`.
Пробник не выдаёт права, не открывает окна, не отправляет события и не
сохраняет их содержимое. JSON содержит только состояние разрешений/tap и
агрегированные счётчики; code0 означает эти условия на двухсекундном
интервале, code1 — отказ, code2 — отсутствуют существующие разрешения.
Нулевой счётчик callbacks не доказывает физическую доставку ввода.

В alpha.6 baseline зафиксировал один disabledUserInput при первом запуске;
удаление лишнего начального tapEnable(false) устранило его в сравниваемом
прогоне. Отдельный проверяемый редакторский сценарий остаётся обязательным.
