# Локальная история диагностических исходов MacSwitcher

`script/collect_diagnostics.py` — отдельный офлайн-сборщик. Установленный MacSwitcher
alpha.33 уже пишет закрытые диагностические события в macOS Unified Log при включённом
`com.macswitcher.metadataDiagnosticsEnabled`. Сборщик читает только subsystem
`com.alexfisenkov.macswitcher`, category `Diagnostics`; сохраняет время и точный
закрытый код исхода. Он не запрашивает Accessibility, Input Monitoring, поля,
буфер обмена или сеть. Из записи Unified Log в журнал не попадают PID, bundle ID,
название окна, URL, текст, отдельные клавиши и произвольные строки. Семейство
`browser` в старых записях объединяет Chrome и Safari. Новые семейства
`chrome` и `safari` различаются только после установки версии MacSwitcher,
которая их пишет. `vsCode` обозначает стабильный VS Code; другие каналы
остаются `other`. `claude` обозначает официальный Claude; `claudeSecondary`
появляется только при включённой диагностике и точном локальном значении
`com.macswitcher.diagnosticsClaudeSecondaryBundleID`, которое в события не входит.

## Установка для постоянного локального наблюдения

Команды выполняются в корне проверенной копии проекта. Пример размещает код
и журнал в локальном профиле Mac, вне репозитория. Для первого сохранения уже
имеющейся истории укажите явный интервал: `--backfill-hours 8` читает максимум
восемь часов, если диагностика включена. Это доступно только до первого запуска
сборщика; без флага первый запуск начинает наблюдение с текущего момента. Один
вызов обрабатывает не больше четырёх 15-минутных страниц; оставшийся интервал
будет обработан следующими вызовами `once` или установленным LaunchAgent.

```sh
diagnostics_dir="$HOME/Library/Application Support/MacSwitcher/Diagnostics"
mkdir -p "$diagnostics_dir"
chmod 700 "$diagnostics_dir"
install -m 600 script/collect_diagnostics.py "$diagnostics_dir/collector.py"
/usr/bin/python3 "$diagnostics_dir/collector.py" once --backfill-hours 8
/usr/bin/python3 "$diagnostics_dir/collector.py" status
/usr/bin/python3 "$diagnostics_dir/collector.py" report --hours 8
```

Если проход сообщил `scan failed`, проверьте причину через `report` и повторите
`once`. Успешно прочитанные страницы уже продвигают курсор, неудачная страница
не пропускается. После трёх подряд превышений лимита объёма или времени на
одной странице сборщик явно помечает её как пробел `query budget` и продолжает
со следующей страницы. При других ошибках курсор остаётся перед неудачной
страницей. Максимальный срок догоняющего чтения — 24 часа.

После проверки первого прохода создайте собственный LaunchAgent. Генератор
подставляет абсолютный путь именно к установленной копии скрипта:

```sh
agent="$HOME/Library/LaunchAgents/com.alexfisenkov.macswitcher.local-diagnostics.plist"
/usr/bin/python3 "$diagnostics_dir/collector.py" plist > "$agent"
chmod 600 "$agent"
plutil -lint "$agent"
launchctl bootstrap "gui/$(id -u)" "$agent"
launchctl print "gui/$(id -u)/com.alexfisenkov.macswitcher.local-diagnostics"
```

Agent вызывает `once` при загрузке и раз в 60 секунд. Повторные проходы читают
перекрывающийся интервал и удаляют дубли по идентичности записи Unified Log;
отдельные события с одинаковым кодом остаются отдельными. На один запуск
отводится не более четырёх страниц и двух минут. После сна сборщик постепенно
догоняет максимум 24 часа и показывает пропуск для более старого интервала.
Unified Log сам может утратить события раньше; отсутствие записи не доказывает,
что жест не произошёл. При неудачном запросе журнал фиксирует счётчик отказов;
`status` и `report` показывают курсор и оставшийся повтор лимитной страницы.
Журнал хранит не больше 14 дней, 6000 событий и 1 МиБ;
каталог имеет права `0700`, файлы `0600`. Файлы в этом каталоге не публикуйте.

## Просмотр и остановка

```sh
/usr/bin/python3 "$diagnostics_dir/collector.py" report --hours 24
/usr/bin/python3 "$diagnostics_dir/collector.py" status
/usr/bin/python3 "$diagnostics_dir/collector.py" stop
launchctl bootout "gui/$(id -u)" "$agent"
```

`stop` сразу запрещает новые чтения даже если LaunchAgent ещё запущен; `bootout`
выключает расписание. Пока расписание выключено, срок хранения на диске не
пересчитывается: старые записи удаляются при следующем запуске сборщика.
Возобновление начинается с текущего момента, без импорта
интервала остановки:

```sh
/usr/bin/python3 "$diagnostics_dir/collector.py" start
launchctl bootstrap "gui/$(id -u)" "$agent"
```

Если диагностика отключена в самом MacSwitcher, `once` не читает Unified Log и
при повторном включении тоже начинает с нового момента. Остановка сборщика
не удаляет прежние записи из macOS Unified Log. Локальный журнал остаётся
доступен для `report`; при желании его можно удалить после
`stop` и `bootout` как обычный локальный файл `journal.json`. Это не управляет
внутренним хранилищем Unified Log macOS.

`report` показывает старейшую/новейшую сохранённую запись, известные пробелы,
счётчик неудачных проходов и все исходы `combined.*`/`automatic.*` за период,
без обрезки. Исходы, разделённые не более чем тремя секундами, объединяются в
эпизод; рядом с каждым исходом перечислены закрытые коды его эпизода в окне
±3 с: код относится к первому исходу после него, иначе к последнему исходу
эпизода. Это соседство по времени, а не доказанная причинная связь. Строка
`Double Shift` сводит распознанные двойные нажатия с их итогами: исправлено,
отказ, текст исправлен без подтверждённой раскладки, завершилось раньше.
Сборщик читает уровень `notice` без `--info`; одна 15-минутная страница
ограничена 30 секундами запроса, один запуск — 120 секундами. Отказ до определения адресата может
иметь семейство `other` или только общий код `double*`. Журнал не устанавливает,
в каком окне или на каком сайте произошло событие. Если Unified Log сообщает
`processImagePath`, сборщик допускает только путь исполняемого файла установленного
MacSwitcher; старые строки без этого поля допускаются по subsystem/category и
закрытому коду, поэтому происхождение таких строк дополнительно не доказано.
