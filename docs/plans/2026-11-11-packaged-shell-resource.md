# Ресурс shell-подключения внутри установленного приложения

На живой установке первого кандидата alpha.31 (`62dced1`) preview настройки
показал путь `macos/.build/.../terminal-zle.zsh`, хотя копия скрипта присутствовала
в `MacSwitcher.app/Contents/Resources/RuSwitcher_RuSwitcher.bundle/`.
Настройка отменена до записи профиля; подключение shell выключено до исправления.
Пользовательские настройки и данные обучения после установки сверены с копией:
прежние ключи не изменились, хеши словарей совпали, интервал 200 мс сохранён.

Причина — сгенерированный SwiftPM `Bundle.module`: fallback к build-directory
на машине сборки маскировал несоответствие packaged-layout. Наличие файла в ZIP
и успех прежнего resource self-test не доказывали выбор этого файла приложением.

## Минимальное исправление

- Реальный `.app` разрешает только свой вложенный resource bundle и читаемый
  обычный shell-скрипт. Отсутствие файла возвращает `nil`, без build fallback.
- App, bundle и файл приводятся к canonical/resolved путям; выход через symlink
  за пределы приложения или его resource bundle отклоняется.
- SwiftPM/dev вне `.app` сохраняет прежний `Bundle.module`.
- Существующий `--self-test-resources` дополнительно проверяет фактически
  разрешённый путь shell-скрипта и возвращает ненулевой код при нарушении.

## Gate

Независимая Luna code/deps/skeptic-проверка: R1 WARN symlink escape исправлен,
R2 PASS по исходникам. Адресные filesystem tests — 13/13; реальная холодная
проверка пакета выполняется отдельно: положительный запуск и отрицательный
с временно убранным тестовым ресурсом при доступном build fallback.

Повторный hosted CI допустим именно из-за этого подтверждённого runtime-дефекта
после первой установки; это не промежуточный запуск для незавершённого кода.
Старые CI/артефакт/подпись `62dced1` сохраняются как история, их не перезаписывают.
Новый signed/notarized кандидат имеет собственный source SHA и каталог.

После пересборки обязательны: preview с путём внутри установленного `.app`,
сверка профиля/backup, явное разрешение macOS и проверка Terminal обычным вводом.
Первый кандидат уже установлен; успех его внутренних 4/4 не является
подтверждением работоспособности ещё не подключённого shell-backend.

## Подтверждённая локальная проверка

После исправления: full Swift646/646 PASS в изолированном профиле. Новый
ad-hoc `.app` действительно запущен с `--self-test-resources`: exit0 и
`shellBridgeResourcePackaged:true`. В собственной disposable-копии пакета
скрипт временно переименован, dev fallback на машине оставался доступен:
exit2 и `shellBridgeResourcePackaged:false`. Файл восстановлен, codesign verify
прошёл. Установленное приложение и пользовательский профиль этим тестом
не менялись. R2 независимого code/deps/skeptic-критика — PASS по исходникам;
холодный CLI прогон выполнен отдельно главным агентом.
