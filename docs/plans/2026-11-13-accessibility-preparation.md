# Подготовка доступности приложений · alpha.33

## Основание

Владелец подтвердил обычный клавиатурный ввод `ghbdtn` в Codex без автоматической коррекции на alpha.32. В близком временном окне зарегистрированы отказы начального якоря (`autoAnchorStale`); эти метаданные не содержат текста и не доказывают конкретную причину каждого отказа. В том же процессе были и подтверждённые автозамены, поэтому глобальное выключение движка не установлено.

Найден конкретный пробел подготовки AX: `ElectronAccessibilityBridge` допускает приложение только при наличии буквального `Electron Framework.framework`. У установленного клиента с bundle ID `com.openai.codex` внутренний framework называется иначе. Наличие ресурсов Chromium и `app.asar` не доказывает поддержку Electron-specific setter. Проверка имени не должна быть условием безопасного чтения стандартной роли приложения.

В [исходнике Chromium](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/chrome_browser_application_mac.mm) чтение роли приложения используется для инициализации базовой доступности. В проекте такое чтение уже есть в диагностическом `inspect`, но отсутствует в обычной подготовке приложений. [Electron](https://www.electronjs.org/docs/latest/tutorial/accessibility) отдельно документирует `AXManualAccessibility`; переносить его на неподтверждённый Chromium runtime нельзя. Чтение роли в установленном Codex вернуло стандартную роль приложения; доступность его активного поля и связь с жалобой ещё требуют проверки.

## Минимальное изменение

- На активации и существующем двухсекундном опросе готовить текущий процесс стандартным чтением только `AXRole` приложения, независимо от имени framework. Не читать поле, содержимое, выделение или буфер обмена.
- Сохранить прежний Electron-specific setter только для ранее поддерживаемой структуры. Не добавлять `AXEnhancedUserInterface`, режим screen reader или список имён приложений.
- Сохранить проверки доверия, защищённого ввода, удалённой сессии, идентичности процесса и исключение самого MacSwitcher. Запрос выполняется вне callback клавиатуры, с конечным таймаутом; успешная подготовка не повторяется без основания.
- Не менять распознавание слов, Shift, якорь первого ввода, безопасную запись, проверку PID/поля/ревизии/каретки и поведение при неизвестном глобальном фокусе.
- Успешная подготовка означает только завершение запроса роли/существующего Electron-механизма. Она не подтверждает готовность поля или доставку текста.

`refresh()` уже подключён в `AppDelegate` к двухсекундному опросу. Предварительная гипотеза об отсутствующем вызове опровергнута чтением этого участка; менять wiring ради неё не требуется.

## Проверки и границы

Сначала RED для активного приложения без буквального Electron framework, затем минимальная реализация. Проверить отсутствие лишнего Electron setter, сохранение прежнего Electron пути, безопасные отказы, повтор после временной недоступности и идемпотентность. Использовать изолированный Foundation-профиль; данные владельца не являются fixtures.

После локального набора прошли финальная CI, подпись/notarization и штатная установка с сохранением данных. Владелец кратко подтвердил положительный результат теста в Codex и разрешил публикацию alpha.33 в GitHub. Это подтверждение не задаёт протокол повторных проверок и не доказывает устранение исходной причины.
