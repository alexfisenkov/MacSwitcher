# Двойной Shift: возможности поля вместо списка приложений

## Требования

Продолжение существующего поведения: одиночный Shift меняет раскладку,
двойной исправляет последнее слово или выделение, подтверждённую правку
можно отменить и повторить; следующее слово также доступно. Пользователь
попросил поддерживать классы похожих приложений, а не частные исключения.
Существующие тайминги, словари, обучение и согласие на recovery не меняются.
В частности, сохраняется пользовательский интервал владельца 200 мс;
заводское значение 180 мс не изменяется этим исправлением.

Редактируется только доказанная цель ввода. Неоднозначный, защищённый или
неизменяемый текст не получает пакетов записи. Никаких Enter, исполнения
команд, слепого удаления по числу клавиш или clipboard-fallback после
неопределённой записи.

## Подтверждённые различия

- При активном поиске по Command+Space на текущей macOS поле Campo было
  AXTextField с доступным выделением и положительными setters. Его PID
  совпал у видимого окна, systemwide AX и прямого AX-фокуса; NSWorkspace
  продолжал указывать на приложение под поиском. Старый manual-путь
  ошибочно использовал только NSWorkspace.
- Активная новая строка Terminal показала AXTextArea: выделение доступно,
  но текст/значение не предоставлены как изменяемое поле. Это область
  отображения терминала, а не API командного редактора. Исправлять её как
  обычный текстовый документ нельзя. На тестовом Mac используется zsh.
- Снимались метаданные без содержимого поля. Тестовый `ghbdtn` введён
  пользователем без Enter; команды через Terminal не отправлялись.

## Адаптеры

### Нативное поле

Сохраняется существующий native-путь с точным PID, AX-элементом, диапазоном,
ревизией, layout и input lease, проверкой результата всего поля.

### Плавающее поле

На первом коротком Shift отдельно фиксируются host жеста и фактическая цель.
Допуск основан на совпадении systemwide/direct AX и конкретного видимого окна,
положительных возможностях редактирования и secure/read-only проверках.
Название приложения не является списком допуска. Для нескольких окон цель
однозначно связывается через публичную геометрию AXWindow/CGWindow.
Неоднозначность не возвращает запись в окно под поиском. Проверки цели
повторяются в прежних фазах native-транзакции; обычные буквы не получают
дополнительный поиск AX-цели.

Автокоррекция в таком поле не включается до доказанного недорогого способа
атрибуции события. Вместо этого исключается ошибочная запись в поле под
активной плавающей целью. Обычное поле под неактивным окном Siri продолжает
работать.

### Командный редактор

Отдельный кооперативный протокол изменяет собственный буфер редактора строки
оболочки, а не эмулирует редактирование терминального вывода. Первый backend —
zsh/ZLE; протокол и доказательство фокуса не привязаны к имени Terminal.app.
Другой терминал может использовать те же возможности, когда подтверждена
связь текущей поверхности, вкладки/TTY и зарегистрированного процесса.
Этот backend обслуживает явный ручной двойной Shift. Потоковое чтение
команд и автоматическое исправление командной строки в него не добавляются.
Из shell-команд не записываются новые голоса адаптивного обучения. Это
явное ограничение первого backend: подтверждения/отмены обычных редакторов
продолжают использовать прежний контур обучения, личный словарь и его данные
не мигрируются и не очищаются. Для обучения из shell необходим отдельный
word-only provenance-контракт, а не подставной AX-идентификатор.

Локальный брокер принимает только проверенного peer UID/PID, готовую сессию и
свежий nonce. Commit сверяет полный ожидаемый буфер, позицию и выделение;
дубликат запроса возвращает сохранённый результат без повторной мутации.
Текст не попадает в argv, environment, логи или сеть. Выделение вывода вне
буфера команды не разрешает менять саму команду. Неизвестная доставка требует
запроса статуса/сохранения исходника, а не слепого повторения.

Подключение профиля оболочки и возможный доступ к метаданным активной вкладки
— отдельный явный шаг после подготовки и проверки кода. Реальные `.zshrc`,
история, настройки Terminal и TCC не изменяются в ходе прототипирования.
Сначала проверяются резервная копия, идемпотентность и удаление ровно
собственной source-строки на временных профилях.
Ресурс подключается к новым интерактивным zsh-сеансам. После перезапуска
MacSwitcher или отключения/включения shell-функции уже открытая строка может
потребовать нового окна/приглашения оболочки: приложение не отправляет
`source`, Enter или другие команды для переподключения в пользовательский
терминал. Это ограничение доступности первого backend, не автоматическая
поддержка всех уже открытых терминальных сеансов.

## Проверки и статус

Для плавающих целей реализован общий proof и адресные регрессии; замечания
двух раундов критики обработаны, включая remaining-time checks перед каждым
AX RPC. Проверка реального ввода и задержки остаётся открытой.
Для ZLE проверен отдельный PTY-прототип без Enter; локально добавлены
production-брокер, обнаружение read-only SDEF-возможностей выбранной вкладки,
проверка её TTY/foreground process group и подключение к combined-жесту.
Подключение выключено до явной настройки. После замечаний R1 добавлены
привязка к полю первого жеста, повторная сверка выбранного TTY после AX,
отмена по новой ревизии ввода, резерв исходника до CAS и запрет выхода во
время неопределённой доставки. Заключительная независимая проверка открыта.
Выделение мышью допускается только при точном bounded AX-хвосте BUFFER,
одной визуальной строке и повторной проверке диапазона; неподтверждённое
выделение вывода не получает last-word fallback.
Это не заявление о готовой поддержке Terminal или всех терминальных программ.

Финальный CI запускается после согласованного набора изменений. Пакет,
установка, разрешения и физическая приёмка учитываются отдельно от synthetic
PASS. Пользовательские тексты и файлы восстановления в Git/fixtures не входят.
Общий изолированный локальный прогон адаптеров 10.11: 606 Swift-тестов без отказов,
36 Python-проверок, gold495 без ложных/пропущенных замен; статические проверки
309 публичных файлов, HTML/локальных ссылок и inline JavaScript прошли.
Этот результат не доказывает TCC, профиль, физический жест или установку.
После него владелец расширил задачу самодиагностикой и безопасным
восстановлением; это дополнение реализуется до общего hosted CI по
[отдельному плану](2026-11-10-runtime-health.md). Базовые результаты адаптеров
не подменяют проверку ещё разрабатываемого health-кода.

## Матрица приёмки текущей ветки

| Сценарий | Требование | Статус |
|---|---|---|
| Обычный редактор | Одиночный жест, повторный double, новое слово, прежние настройки | Общий Swift606 PASS; физическая приёмка открыта |
| Плавающее поле | Только фактическое systemwide/direct поле, без записи в подложку | Probe-регрессии добавлены; живой ввод ожидается |
| Медленный AX-провайдер | Поэтапный deadline, отказ без последующих RPC | R2 исправлен и покрыт regression; CG scan непрерываемый |
| Командный буфер | Exact BUFFER/cursor/region/nonce CAS, без Enter | Изолированный PTY прошёл; production-приёмка ожидается |
| Смена вкладки/окна | Не редактировать прежнюю или новую недоказанную цель | R1 исправлен; R2 и реальная приёмка открыты |
| Потерянный ACK и Quit | Сохранить исходник до определённого результата/архива | Резерв/quit-gate и reconciliation tests PASS; R2 открыт |

| Другие терминалы/оболочки | Положительный capability proof, отсутствие привязки к имени | Универсальная гарантия не заявляется; другие backend открыты |
