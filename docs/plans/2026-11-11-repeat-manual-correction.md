# Повторное ручное исправление shell-строки · 11.11.2026

После узкой физической проверки `ghbdtn` + пробел + двойной Shift в Terminal
проверен локальный контур повторного жеста. Автоматическое исправление команд
не входит в этот backend.

## Дефект и правка

`ManualShellCoordinator` хранил подтверждённые состояния строки для undo, но
при повторном жесте сравнивал прежний BUFFER и CURSOR без MARK и REGION_ACTIVE.
Если пользователь после исправления выделял часть той же строки, старый путь
предлагал восстановить весь исходный BUFFER и снять выделение. RED-регрессия:
после `echo ghbdtn` → `echo привет` выделено только `вет`; исходный код предлагал
`echo ghbdtn` вместо адресного изменения выбранной части. Условие receipt-undo
теперь требует совпадения всего состояния выделения. При изменённом ZLE-region
действует обычный путь преобразования выделенного диапазона.

## Локальная проверка и границы

Адресный набор `GenericShellEditor|ManualShellCoordinatorPolicy|ShellStartupRetryPolicy`
прошёл 24/24 в отдельном `CFFIXED_USER_HOME`. Новый расширенный PTY-тест прошёл
1/1 после последних test-only additions: последовательные CAS для исправления,
undo, redo, отказа старому prepared-снимку и следующего слова после двух
пробелов. Forced timeout 0 проверил переход в uncertain и readonly query с
reconciliation; это не имитация реальной потери пакета/ACK. Отдельная fixture
проверила disconnect, line-init и connect существующего PTY после broker restart:
new nonce, сохранение буфера и CAS прошли.

Synthetic overlay coverage проходит через integrated production routing; это
не проверка AppDelegate или HID. Установленный Terminal не переподключался после
broker restart, поэтому live Terminal reconnect остаётся неподтверждённым.
Физическая проверка повторного жеста/выделения ограничена ранее подтверждённым
вводом `ghbdtn` + пробела с двойным Shift. Spotlight проверяется своим независимым
контуром.
