# Foreground-проверка shell из GUI-процесса

## Узкая физическая приёмка · 11.11.2026

На установленной alpha.31, собранной из `261bdc25c36cb2edb54642d773e97e585473ede6`,
владелец физически набрал в Terminal `ghbdtn`, поставил пробел и нажал двойной
Shift; сообщил, что текст исправился на правильное слово. Подтверждена только
ручная замена последнего слова после пробела. Этот результат не подтверждает
undo/redo, исправление следующего слова, автозамену или Spotlight.

Владелец выбрал политику: защищать команды, в Terminal доступен только двойной
Shift. Автоматическое исправление команд по пробелу или во время набора не
ожидается; политика автозамены в других обычных редактируемых полях сохраняется.

После успешной настройки профиля и сообщённого пользователем разрешения
Automation физический `ghbdtn` в Terminal не исправился. Агенту инструмент
управления UI запретил доступ к Terminal; это ограничение не обходили.
Проверка выполнена на собственной изолированной PTY, без пользовательского окна.

Подтверждённый дефект: прежний `shellIsForeground` открывал slave TTY через
`O_NOCTTY` и вызывал `tcgetpgrp` из фонового GUI. В таком контексте на этой
macOS вызов возвращает `ENOTTY` (25), даже когда дочерний shell владеет
foreground-группой своей PTY. Unit-тесты брокера использовали подменённую
foreground-проверку и не подтверждали этот системный контракт.

## Исправление и критерии

Нельзя удалять foreground-guard или доверять только имени приложения.
Нужен публичный системный источник metadata: точный PID/UID, controlling TTY
device, process group и foreground group. Данные сверяются с выбранной TTY;
ошибка/неизвестность отклоняют запись. Аргументы, окружение, память и текст
команд не читаются. Прежние peer, SDEF/AX, nonce/CAS и input revision gates
сохраняются.

Тесты должны запускать настоящий production-validator из родителя без
controlling TTY на собственной PTY: foreground-случай проходит; неверная TTY,
отсутствующий PID и временно foreground-другая собственная группа отклоняются.
Никаких Enter, пользовательских команд или обращения к пользовательскому
Terminal. Cleanup касается только процессов/PTY тестовой фикстуры.

Дополнительный hosted CI/артефакт после `c507fdf` обоснованы этим реальным
отказом, а не промежуточной разработкой. Профиль уже содержит стабильный путь
внутри приложения и не требует новой строки после исправления. После нового
запуска app нужен новый prompt для reconnect; тестовое `ghbdtn` можно отменить
Ctrl+C без выполнения команды. Реальный double Shift принимает пользователь.

## Проверка перед поставкой

Writer проверил исправление на собственной PTY в изолированном профиле: полный
набор Swift 647/647 и release build прошли. Независимая статическая проверка
`foreground_kernel_review` по code, risk и skeptic завершилась PASS без
существенных находок. При финальной CLI-сверке отдельно прошёл новый тест
production-validator на настоящей PTY (1/1), Python 36/36,
`check_public.py` (316 файлов), `check_website.py` и `git diff --check`.
Изолированный профиль `CFFIXED_USER_HOME` для Swift подтверждён через
Foundation `applicationSupportDirectory`. Это не является проверкой
пользовательского Terminal, физического double Shift или установки приложения.
