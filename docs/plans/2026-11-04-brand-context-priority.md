# Русский контекст после английского названия

## Задача и решение владельца

Владелец подтвердил исправление подавления коротких русских слов после английского слова/бренда. Английское название сохраняется, следующие русские слова снова получают русский приоритет. Это исправление конкретной словарной политики; оно не объявляется доказательством устранения всех отказов редактора.

## Общий контракт macOS/Windows

- При русском приоритете ON одиночное известное название (категории brand/name/place в существующем protected-terms.tsv) не является доказательством английской фразы. Само название сохраняет прежнюю защиту от конверсии.
- Частотные омонимы в нижнем регистре (`long`, `red`, `line`, `reason`) остаются обычным английским сигналом: название нейтрально для контекста только при заглавной букве в отображённом токене либо EN-частоте <5000. Проверка одинакова и для раннего `yt`.
- Категории word/abbreviation и явные технические подсказки не приравнивать к брендам. Технические подсказки остаются защитой; адреса, пути, кодовые формы и явные пользовательские исключения имеют прежний приоритет.
- Явное русское слово в последних трёх словах контекста прекращает действие более раннего английского сигнала. Одиночная английская вставка после этого русского слова не должна захватывать контекст; два следующих обычных английских слова могут снова подтвердить английскую фразу. Названия не считаются обычными английскими словами.
- При отсутствии русского контекста обычное английское слово остаётся английским сигналом. Неизвестные mixedCase идентификаторы сохраняют прежнюю осторожность; изменение не должно превращать `press f`, `hello f` или настоящую английскую фразу в русский текст.
- При русском приоритете OFF, явном исключении, личном слове/обученном предпочтении и неправильном mapping остаются прежние правила.
- Использовать существующие категории TSV в памяти; не менять словари/лицензии/формат пользовательских данных, ресурсы или зависимости. Fixture constructors получают необязательные аргументы для классификации названий.
- Не менять input/AX/source/fence/secure-input guards, жесты и 180 мс. Не читать личные словари или реальные тексты для тестов.

## Расширение по подтверждённому undo-дефекту

Производственная регрессия обнаружила два реальных отказа: double Shift возвращает `f`, но следующий пробел снова делает `а`; после обхода пробела следующее сильное русское слово дополнительно переписывает явно сохранённое `f`. Windows read-only аудит нашёл аналогичный незакрытый путь. Простое подавление одного точного предложения/TTL не выражает выбор пользователя.

Подтверждённая отмена автозамены становится границей предсказания: продолжение явно оставленного слова не переписывается, после его разделителя новое слово снова предсказывается, а предыдущее не ремонтируется задним числом. Если отмена уже завершилась после пробела, новое слово разрешено сразу. Новый идентичный токен остаётся новым случаем, а повторный двойной Shift без допечатывания сохраняет redo.

macOS writer дополнительно владеет PredictionSnapshot/KeyboardMonitor/PredictionCoordinator и соответствующими регрессиями. Windows writer — runtime и собственными synthetic contract/fixture tests. Новое состояние только bounded RAM, с привязкой к проверенному полю и исходнику, без журналов текста/диска/новых настроек; transport/fence/source verification остаются прежними. Это согласованное parent расширение по RED, не ослабление проверок записи.
