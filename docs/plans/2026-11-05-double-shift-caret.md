# Повторный отказ двойного Shift · 05.11.2026

## Наблюдение

Владелец сообщил: одиночный Shift продолжает переключать раскладку, двойной
перестал исправлять текст в разных приложениях. Установлена alpha.28.
Перед перезапуском сохранена opt-in диагностика только закрытых этапов:
11 распознанных двойных жестов, каждый завершился
`failure.wordNativeCaretMismatch` → `failure.wordNativeEditRefused` → отказ.
Это отказ **до записи**, а не отсутствие клавиатурного события.

Прежний код объединял отсутствие начального диапазона, неколлапсированный
диапазон и позицию короче буферного суффикса. Поэтому журнал ещё не доказывает,
какой из этих вариантов вызвал исходную жалобу. Не считать восстановление
после перезапуска доказательством устранения причины.

## Граница исправления

- Разделить причины каретки закрытыми идентификаторами без текста, диапазонов,
  клавиш, PID и произвольных строк.
- До первой записи сравнить длину буферного слова с исходной позицией каретки.
- Если буфер длиннее доступного префикса, разрешить только существующую проверяемую операцию
  над фактическим последним словом: то же поле/PID/revision, исходная
  коллапсированная каретка в конце ограниченного поля, актуальный источник,
  повторное точное чтение поля и действующий input lease.
- После поставленной в очередь либо неоднозначной записи другой способ
  редактирования не запускать. Прежние selection/undo/reconvert и явно
  включённый режим всей строки сохраняют свой порядок и смысл.
- Отсутствующая начальная каретка, смена поля/каретки/источника, secure/read-only
  и недоступный AX остаются отказом без записи.
- Тайминги Shift, словари, обучение и пользовательские настройки не менять.
- Дополнительные AX-запросы на обычном словном маршруте не добавлять:
  предварительное чтение может израсходовать 250-мс lease до записи. Буфер
  допустимой длины, но с иным текстом, пока остаётся отказом без записи.

## Проверка и пределы

Сначала RED на production-пути с устаревшей непустой историей и реальным
последним словом в синтетическом поле. Затем исправление, повторные undo/redo
и новое слово; отрицательные случаи должны оставить поле и источник без
изменений. Локальные тесты — только с новым `CFFIXED_USER_HOME`.

Отдельно проверить код независимыми критиками, полную Swift suite и один
финальный macOS CI для согласованного исходника. Подпись, notarization,
установка и физическая приёмка — отдельные свидетельства.

Не менять Windows-компонент: показанный отказ относится к macOS AX/native
маршруту. Синхронное чтение AX на первом ShiftUp требует отдельного исследования,
если новые коды покажут недоступный начальный диапазон; текущего журнала для
такого вывода недостаточно.

## Статус

Причина повторного отказа локализована до проверки каретки перед записью.
Реализовано ограниченное восстановление последнего слова. Code-review выявил
риск лишнего предварительного AX-чтения; RED с задержкой 60 мс воспроизвёл
отказ корректного буфера. Дополнительные чтения убраны: целевые transaction
44/44, полная изолированная Swift suite 543/543, Python 35/35 PASS.
CI, выпуск и физическая приёмка ещё не подтверждены.
Подтип исходного live-отказа не установлен; закрывать его
по одному успешному синтетическому сценарию нельзя.
