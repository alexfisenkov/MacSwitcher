# Общая блокировка после неподтверждённых замен · 09.11.2026

## Подтверждённое наблюдение

Установленный alpha.29/e96e9cd работал одним процессом с 5 ноября. Одиночный
Shift работал, двойной распознавался и отказывал на `unconfirmedEditBlocked`.
После штатного сохранения при выходе локально проверено только количество:
в архиве ровно восемь исходников. Содержимое не выводилось и не использовалось
как тестовые данные. Файл 0600 дополнительно синхронизирован вместе с каталогами.
Тот же alpha.29 перезапущен; мастер включён, combined Shift включён, 200мс.
Это временное восстановление; физическая клавиатура после него отдельно не
подтверждена.

Причина общей блокировки: восемь RAM-записей неизвестной доставки заполняют
глобальный лимит. Защита не истекает по времени и переживает `clearState`.
Простое удаление записей потеряло бы единственные исходники и разрешило
слепой повтор в неопределённом поле.

## Решение

- Сохранять 8 RAM-полей и бюджет 1 048 576 UTF-16 единиц.
- Достоверная локальная копия даёт receipt только после точного read-back,
  SHA-256, прав 0700/0600 и fsync файла/каталогов. Неподтверждённые записи
  никогда не удалять из RAM ради места.
- Сохранённые RAM-записи остаются для прежней явной реконверсии. При
  заполнении ёмкости фоновая очередь проверяет самую старую сохранённую запись;
  в RAM остаётся блокировка её точного PID/AX-поля и ссылка на архив. Перед
  освобождением оригинала доступность копии повторно проверяется фоновой
  очередью; ввод не выполняет дисковые чтения. При заполнении лимита эта
  подготовка освобождает запас до следующей правки, сохраняя свежую RAM-запись.
- Архивирование не подтверждает результат исходной замены и не снимает
  блокировку затронутого поля. Другие поля получают свободную ёмкость.
- Завершение процесса снимает только его архивные AX-блокировки; исходники
  на диске и несохранённые RAM-исходники не удаляются.
- Лимиты архивных блокировок и диска конечны: 256 блокировок, 256 экспортов,
  1ГиБ. Автоматического удаления архивов нет; при ошибке/лимите RAM сохраняется
  и показывается понятное действие сохранения/открытия папки.

## Согласие и приватность

Владелец отдельно разрешил автоматическое локальное сохранение только
исходников неподтверждённых замен, с пояснением о возможном полном содержимом
поля. На его Mac настройка включается после проверенного обновления.
Для новых пользователей default OFF, включение явно объясняет хранение.
На установке владельца агент отдельно включил настройку в UI по полученному
согласию и проверил сохранённое значение после установки alpha.30; адресной
миграции или включения всем пользователям в коде нет.
Обычный набор, успешные замены и `preparationUncertain` до Unicode не
архивируются. Это не обучение словаря и не история клавиш. Сети нет.

Экспорт выполняется вне input lease на последовательной фоновой очереди;
ручное сохранение использует тот же безопасный путь. Повторно отправлять
неподтверждённую замену после сохранения запрещено. При ошибке копии исходники
остаются в RAM. Чтение сохранённого оригинала — только по явному действию.

## Приёмка

Production-регрессии: 8 неопределённых полей, отказ девятого без копии,
успешная копия и доступность девятого другого поля, сохранение блокировки
старого поля, доступность явного восстановления свежей RAM-записи; сбои
fsync/read-back, неверный receipt, отсутствие тихой потери или повторной записи.
Автоматика: off/opt-in, фон после lease, объединение задач и корректная обработка
ошибки/отключения. Локальные профили тестов изолированы.

Полная suite, независимые критики, финальный CI, подписанный пакет и установка
проверяются отдельно. Spotlight/Campo и Terminal не входят в эту причинную
правку и остаются отдельной совместимостью.
