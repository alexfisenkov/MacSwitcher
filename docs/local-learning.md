# Локальное обучение на исправлениях

## Решение владельца · 3 ноября 2026

Запрос: приложение само запоминает полезный выбор слова на каждой машине,
после повторного случая, и перестаёт применять правило при обратном исправлении.
Владелец подтвердил обе платформы и порог **два независимых случая**. Повторные
undo/redo одного ввода не являются двумя подтверждениями. Обычный набор,
клавиши, фразы, контекст, clipboard, приложения и поля в журнал не записываются.

Это разрешение заменяет прежнее ограничение «только явное ручное добавление»
только для описанного локального механизма. Выученное хранится отдельно от
ручного словаря; ручные записи не удаляются и не переписываются обучением.
Файл пользователя не попадает в репозиторий, диагностику или канал обновлений.

## Поведение

- Сигнал — успешно подтверждённое ручное преобразование одного слова либо
  подтверждённая отмена конкретной автоматической коррекции. Текст и раскладка
  должны быть подтверждены; Unknown, восстановление RAM-исходника, простая смена
  языка и автоматическая коррекция сами по себе не дают голоса.
- RU/EN-пара канонизируется по буквам и точному layout mapping, а не только
  по текущему индикатору языка. Это сохраняет сценарий латинского слова при
  уже включённой русской раскладке. NFC/lowercase — ключ; регистр набора
  сохраняет существующая конверсия. Переписывать орфографию или придумывать
  произвольную текстовую замену этот механизм не должен.
- Первый независимый выбор — кандидат 1/2; второй такой же — активное правило.
  Повторный callback и применение/отмена того же receipt не увеличивают счётчик.
  Отмена ручного выбора отзываёт его голос; если выбор противоречит активному
  правилу, правило снимается сразу. Повторный redo старого случая не обучает заново.
- Обратное подтверждённое исправление в новом случае снимает активное правило
  и начинает противоположный отсчёт с 1/2. Два конкурирующих активных направления
  одной пары невозможны. Автозамена по выученному правилу не обучает сама себя.
- Явные исключения, личные слова, принудительные правила и защиты паролей,
  технических строк/адресов/путей имеют прежний приоритет. Предпочтённая сторона
  активной пары выступает локальным личным словом; кандидаты не влияют на engine.
  Для известного предпочитаемого слова разрешено удержать преждевременную
  автозамену его префикса до появления границы или расхождения с известным словом.
  Положительная выученная конверсия применяется на границе слова; базовое раннее
  предсказание сохраняется. При отключённом обучении не записывать и не применять
  адаптивный слой; ручной словарь продолжает работать.

## Допустимые данные

Только одно слово/короткое буквенное сокращение: предпочитаемое написание
RU или EN длиной 1–64 UTF-16, без цифр, смешения письменностей, управляющих
символов, адресов, путей и секретоподобных длинных идентификаторов. Внутренний
дефис/апостроф допустим. Символы ошибочной раскладки, соответствующие русским
буквам, допускаются только при точной проверке пары; например `j,sxyj`/`обычно`
и варианты ё не должны теряться из-за запятой или backtick. Выделения из
нескольких слов и контекстные исправления нескольких слов не обучают этот слой.
Не добавлять произвольный текст, просто дважды встретившийся при наборе.

Отдельный `adaptive-rules.json`, schema1, максимум 2000 записей и 512 KiB.
Запись: каноническая RU/EN-пара, предпочитаемый язык, счётчик 1..2,
последняя дата подтверждения и непрозрачный идентификатор последнего случая.
RAM-дедупликация ограничена; после удаления/сброса старые callbacks не должны
восстанавливать правило. Использовать generation/epoch: delete/reset/off меняют
его, callback захватывает поколение при постановке в очередь, store атомарно
сверяет поколение перед сохранением. Синхронный эквивалент допустим только с
доказанной сериализацией. Обучение/диск не выполняются внутри input fence или
low-level callback. Полного хронологического журнала нет. Права — как у
существующего приватного личного словаря. Проверить temp/flush/atomic replace,
валидацию/read-back и отказ записи без изменения живого слоя при ошибке.
Повреждённый, чужой schema или oversized файл сохраняется нетронутым; только
обучение отключается с понятным статусом, базовый switcher остаётся доступен.

## Интерфейс и обновления

Одна настройка «Запоминать мои исправления на этом компьютере», пояснение о
локальных данных, список кандидатов/активных правил со счётчиком, удаление
одного правила и отдельный подтверждаемый сброс. Владелец дополнительно подтвердил default ON с понятным пояснением при первом
запуске. Сохранённое явное off не включать повторно. При обновлении старого
профиля отсутствующий новый ключ означает ON; один раз объяснить функцию. После
проверенного обновления включить на текущем Mac владельца по его запросу.
На Windows пользователя удалённого доступа нет: настройка включается локально.
Файл не включается в обычный экспорт ручного словаря автоматически и сохраняется
при обновлении/переустановке. Никаких новых сервисов, моделей, телеметрии и сетевых
провайдеров. Новая функция не меняет транспорт ввода или пороги Shift.

## План и владение

1. macOS writer: новый чистый adaptive policy/store модуль, provenance ручного
   подтверждённого действия и auto undo, lookup/prefix guard, настройка и список,
   synthetic Swift tests. Не писать Windows или общие документы.
2. Windows writer: Core adaptive policy и отдельный store в Storage, provenance
   receipt origin/ID и action, lookup/prefix guard, настройка/список, Core и
   собственные runtime/storage synthetic tests. Не писать macOS или общие документы.
3. Parent: общий контракт/правила проекта, независимые критики, интеграция,
   целевые локальные проверки, одна итоговая CI каждой платформы после собранного
   набора. Повторять только по конкретному обнаруженному отказу и исправлению.
4. Версии/подпись/публикация — отдельные подтверждаемые этапы. Личные данные и
   файл выученных слов не читать для тестов; все тестовые слова синтетические.

## Приёмка

- 1 случай не меняет результат; 2 разных случая активируют правило; одинаковый
  ID/undo/redo/автоматическое применение не набирают подтверждения.
- Обратный выбор снимает правило, не трогая ручные записи; новое противоположное
  правило требует двух независимых случаев. Forget/reset не отменяются redo.
- Конкретный custom word и однобуквенное слово, RU и EN, запятая/ё в исходной
  раскладке, регистр/NFC, неправильный текущий HKL, префикс и граница слова.
- URL/email/path/цифры/много слов/password/Unknown/protected override не обучаются.
- Off отключает запись и применение; ручные исключения/force priority сохраняются.
- Restart/update сохраняет правила; corrupt/oversize/future schema и disk failure
  не ломают базовый switcher и не затирают оригинальный файл.
- UI список/удаление/сброс и обновления без пользовательского экрана; физическое
  поведение отделяется от unit/build, synthetic runtime, CI и публикации.
